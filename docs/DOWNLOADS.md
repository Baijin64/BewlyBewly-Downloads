# BewlyBewly 下载集成

本地开发分支，以 Bilidown 1.2.7 的下载行为为参照，下载核心独立实现，界面使用 BewlyBewly Vue 3。AI、MCP、顶栏背景修复留到后续。

## 当前状态

当前个人维护测试版为扩展 **0.44.2**、助手 **0.2.6**（协议 2）。源码与安装包在 [Baijin64/BewlyBewly-Downloads](https://github.com/Baijin64/BewlyBewly-Downloads) 的私有仓库中供维护者和朋友使用。Chrome ZIP 为 `dist/BewlyBewly-Downloads-0.44.2-Chrome.zip`，另提供签名 CRX 和连接器 MSIX。安装步骤见 [安装说明](INSTALL-DOWNLOADS.md)。

感谢 [BewlyBewly 原项目](https://github.com/BewlyBewly/BewlyBewly) 与 [Bilidown 原作者王子周棋洛](https://zhouql.vip/)。本分支独立维护，不代表原作者继续更新。浏览器扩展更新后需要重载；连接器配置和任务继续使用原本机数据目录。

下载进度复用 Bewly 原有 Progress 组件，使用主题色、6 像素圆角轨道和平滑宽度过渡；明确区分当前视频流/音频流，暂停保留进度且隐藏旧速度，合并与保存附件使用不可计量的处理中动画，完成后才显示已完成。支持减少动态效果和可访问的进度语义。没有新增估算总进度、剩余时间或后台轮询。

新 MSIX 不再内置 Node.js，压缩包约 27.6 MiB，安装文件约 65.1 MiB。保留 FFmpeg、aria2 和精简后的 Windows x64 迁移依赖。已有兼容系统 Node.js 24+ x64 时直接复用；本机使用原有 24.14.1，没有重复安装或升级 Node。

首次从开始菜单打开助手会检测运行环境。缺少或不兼容时，原生窗口提供“下载并安装 Node.js”“重新检测”和官网入口；点击安装后从 Node.js 官方 Node 24 分支获取 x64 MSI，校验 SHA-256 和 Windows 签名后调用 Windows Installer，可能需要 UAC 授权，安装后自动重新检测并启动服务。取消或失败可重试，临时 MSI 清理；安装好的系统 Node 与连接器保留，供后续下载使用。网页端继续使用现有重试提示，GitHub 连接器下载地址等正式发布后再接。

助手的新托盘菜单使用清晰的下载图标、状态区、功能图标、圆角与留白，并跟随 Windows 应用明暗主题。没有待下载任务、活动任务或关机倒计时时，对应操作禁用。双击图标打开下载器，右键打开菜单，退出仍保留原确认与进度保存行为。

助手启用 PerMonitorV2 DPI 适配；托盘和程序图标包含 16 / 20 / 24 / 32 / 40 / 48 / 64 / 128 / 256 像素资源。离屏渲染检查覆盖 100%、125%、150%、200% 的浅色与深色外观；安装后的本机诊断确认为 144 DPI（150%）。预览为开发渲染图，不作为跨显示器实际点击验收证据；高对比度模式回退到系统菜单绘制。

0.2.4 修复首版新菜单实际弹出时右侧裁切的问题：菜单和各行按 DPI 明确分配尺寸，关闭默认文字列的自动收窄。诊断使用与实际托盘相同的菜单控件，本机 150% 下为 402×408 像素，9 个菜单项均处于客户区内。

助手 0.2.6 此前的 41 项原生测试和实际 MSIX 验证证据继续适用，本轮按 SHA-256 确认同一二进制，没有重复运行原生测试。实际 MSIX 已验证系统 Node、FFmpeg 转 MP3、aria2、托盘和管道释放，更新时原记录与设置保持一致。官方 MSI 下载、哈希及 Windows 签名验证通过；缺 Node 机器上的完整 UAC/MSI 交互仍需单独实测。证据见 `dist/native-ui-0.2.6-verification.json` 与 `dist/installed-runtime-0.2.6-verification.json`。

网页下载 UI 保留 0.44.0 的统一选择按钮与开关，本轮改进进度条。64 项扩展测试、类型检查、ESLint 和生产构建通过，CRX3 签名及固定身份检查通过。Edge 本地模拟页验证了浅色蓝、深色紫主题，以及下载列表暂停后保留 62% 并隐藏旧速度；未操作用户真实任务。当前 B 站页面需重载新版后确认，证据见 `dist/download-progress-0.44.1-verification.json`。

此前的最高音质、动态最高画质、命名预设、NFO 说明和默认合集选择继续保留。原生任务、用户设置及旧配置未修改或导入；实际播放优化开关不因 UI 更新而变化。慢网、实际 CDN 切换与重载恢复实测继续按用户决定延后。详见 `docs/DOWNLOAD-PARITY.md` 与 `dist/download-ui-0.44.0-verification.json`。

## 使用流程

- 主页 Dock 的“下载器”管理待下载、下载中、已完成和失败任务，支持搜索、分页、多选、批量开始/暂停/恢复/重试、修改所选配置及移除记录。
- 播放页“下载”保留在点赞、投币、收藏、分享之后的第五个位置。弹窗每次提供“立即下载”和“加入待下载”。
- 检测到合集后直接列出全部 UGC 合集章节，可展开各视频的分 P，支持筛选、反选和范围选择。当前视频默认只选当前分 P，整视频选项包含全部分 P。
- 下载器可以批量粘贴 BV / AV 号、普通链接及短链接；点击“解析并选择视频”统一勾选后，再立即下载或加入待下载。重叠合集的相同视频只显示一次。短链接由助手在限定的 B 站域名间展开，避免扩展升级时新增必需网站权限。
- 设置中配置画质、音质、编码、并发 1～4、保存目录、文件与文件夹规则。文件名和目录有常用方案，变量可点击插入光标位置。任务保存选项快照；修改默认值不影响已加入的任务。
- 可组合或单独下载有声/无声视频、原生音频、MP3、封面、XML/ASS 弹幕、指定语言/全部 SRT、视频资料（NFO）。NFO 额外保存标题、UP 主、简介和原链接，方便本地媒体库整理；普通观看可不选。功能入口开关与附带下载选项分别设置。
- 已完成任务可打开目录、定位文件、交给默认播放器播放，或导出兼容旧版的历史。删除文件与移除记录是两个明确操作。

选择“最高可用”时显示当前参考视频的实际最高规格，例如“最高可用 · 1080P”；批量任务逐个视频和分 P 取其各自的最高画质。画质读取失败可重试；此前手动固定但当前不可用的规格保留并提示，不静默改写用户配置。

音质的“最高可用”显示参考视频的可用最高档；只有普通音轨时显示 64K / 132K / 192K，有 Hi-Res 或杜比时显示相应名称。自动选择优先 Hi-Res，其次杜比，再选最高码率；Hi-Res / 杜比的有声视频会使用 MKV，原生音频分别保留为 FLAC / MKA。

画质包括 360P、480P、720P、720P 高帧、1080P、高码、高帧、4K、HDR、杜比视界及 8K。音质包括 AAC 64K/132K/192K、杜比全景声、Hi-Res。可用性以视频与当前账号为准，不提供试看替代完整视频，不静默降级或转码。

Hi-Res 使用 FLAC 或 MKV，杜比音轨使用 MKA/MKV；视频与音轨直接复制，MP3 转码必须主动选择。默认播放器是否支持相应规格取决于系统与播放器。

## 后台、工具与迁移

关闭浏览器后下载继续。托盘提供打开下载器/设置、开始待下载、暂停、取消关机及退出。支持提示音、可选剪贴板链接监听和空闲退出。

自动关机默认关闭。开启后，本轮任务必须全部成功、无附件警告、待下载和暂停列表为空，且没有辅助工具正在处理，才进入 30 秒可取消倒计时。取消后本轮不再自行安排关机。

辅助工具提供 BV/AV 转换、当前浏览器账号的入站时间查询、CC JSON 转 SRT、SRT 转文本、音频转 MP3、手动混流。源文件不修改，既有输出不覆盖。入站时间由原版所用的官方创作中心接口查询，接口或账号不提供时显示原因。

迁移是可选操作：退出旧版后预览其下载设置，或选择 `.bilidownexport` 历史文件，核对差异和数量后导入。原文件保留，不迁移旧登录信息，不触发重新下载。旧记录只有目录信息，不能据此声称视频文件已核验。旧窗口关闭行为不覆盖新助手的后台与托盘选择；剪贴板、关机不会因导入旧配置而自动启用。

## 网页播放优化

在设置或播放页“播放优化”中主动开启。浏览器仅在开启时申请可选媒体域名与请求观察权限，默认不启用。

检测持续低缓冲卡顿时，对实际观察到的当前媒体流比较有限量的官方备用地址。仅切换同画质、编码和音轨；暂停、拖动、后台节流或缓冲充足但解码丢帧时不进行网络切换。切换失败撤销规则；需要重载时显示按钮，点击后恢复进度、音量和暂停状态。

规则限定标签页及具体媒体资源，导航、过期、关闭功能时清除；状态使用浏览器会话存储，后台工作线程重启时恢复并清理孤立规则。没有外部代理、AI 上传或边下边播缓存。

## 数据与构建

架构：网页 Vue → 扩展后台 → Native Messaging → Windows 宿主 → 独立本地服务 → aria2 / FFmpeg。网页播放优化独立于下载助手，使用浏览器自身网络路径。

任务和设置保存在 `%LOCALAPPDATA%/BewlyDownload/downloads.sqlite`，首次升级到协议 2 前备份数据库。下载会话只提供给本机助手，使用当前 Windows 用户 DPAPI 加密，不写入日志或验证报告。助手接口和 aria2 仅监听回环地址并使用各自随机凭据。

```powershell
npm ci --prefix native --ignore-scripts
npm run typecheck -- --noEmit
npm run test:download
npx vitest run
```

不影响当前已安装扩展的生产构建验证：

```powershell
$env:NODE_ENV = 'production'
$env:BEWLY_BUILD_DIR = 'dist/extension-validation'
npx run-s build:web build:prepare build:js build:bg
```

仅编译未打包助手，用于隔离测试：

```powershell
npm run build:helper -- -StageOnly
```

发布构建不设置 `BEWLY_BUILD_DIR`，使用既有 `npm run build`、`build:helper -- -DevSign`、`pack:crx` 流程。需要 Node.js 24+、Windows SDK 和 .NET Framework C# 编译器；最终 MSIX 自带运行时和工具。固定公开身份位于 `native/identity.json`，签名使用 Windows 证书提供器，不导出私钥，不自动更改证书信任。

界面预览使用 `npx vite --config native/tests/preview/vite.config.ts`，为模拟任务，不访问真实账号。显式真实网络验证使用 `node scripts/verify-download-live.mjs <BV号>`，在独立目录工作，完成后关闭自建服务并移除临时会话副本。

本地二进制来自用户已有的 aria2 / FFmpeg 安装，许可材料随包保存。本分支尚未公开发布或上传。

## 当前手动验收入口

本机助手保持 0.2.6，复用原系统 Node。个人维护发布版扩展为 0.44.2；推荐 ZIP 解压后加载，当前 CRX 的直接安装启用仍未通过验收。其他机器安装 MSIX 后，从开始菜单打开一次；缺 Node 时使用本地窗口安装。此前下载功能验收记录保留，播放优化的慢网实测继续延后。

自动浏览器工具只允许 HTTP / HTTPS，已拒绝访问 edge://extensions，不能代替用户操作扩展管理页。递归替换旧生成目录的操作也被自动审批拒绝；随后采用逐文件备份与更新，更新了 54 个生成文件，没有删除原目录。

0.2.1 使用 CreateProcess 的显式不继承句柄模式启动独立服务。回归测试在旧实现复现了“宿主已退出但管道仍被服务持有”；修复后，安装包的应用别名连续两次请求均完整关闭管道，同时独立服务继续存活。独立真实下载也在桥接退出后完成。
