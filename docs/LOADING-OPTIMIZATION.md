# 0.44.5：保留 UI 的加载与渲染优化

用户确认本阶段只优化网络请求、预览缓存和渲染开销。继续下载 MP4 后用系统播放器观看；不增加离线播放库、独立窗口、老板键或手柄功能。

## 请求与缓存

- 推荐加载改为单一进行中的加载周期：重复触底合并，每周期最多取 3 页，连续两页没有新卡片时停止补页。错误不会递归重试，失败页码保留，可刷新重试。
- 刷新、切换推荐模式、停用页面或隐藏标签页时取消请求；旧代次的返回结果不再写回。重新进入时保留已有卡片，不裁剪列表或更改滚动位置。
- App 推荐按服务端原始列表的末尾游标推进，包括被过滤的条目，避免反复请求同一页。重复视频按标识去重。
- 新的只读请求桥仅处理推荐、视频资料和悬停预览四种固定官方接口。相同进行中的请求合并；最多同时运行 4 项，预览类最多占 2 项，排队时推荐请求优先。
- 视频资料在内存缓存 60 秒，预览地址最多 30 秒，并提前避开签名失效时间。推荐结果不缓存。切换登录账号或关闭标签页会清理相应请求、缓存；不持久保存地址或记录。
- 每个调用方独立取消，共享请求仍有其他调用方时继续；最后一个调用方离开后终止网络请求。后台请求与浏览器消息都设有超时。
- 悬停离开、页面停用或组件卸载时取消预览、清理计时器；过期地址重新解析，预览失败保持封面与原视频链接可用。

这部分优化减少重复请求与预览抢占带宽，不接管官方播放器的媒体分片缓存，不改画质、音轨、播放顺序或已授权的线路优化。跨境媒体吞吐和真实慢网线路切换仍需单独实测，不能据此承诺具体加速比例。

## 渲染

推荐数据进入列表时只构造一次卡片属性对象，列表使用浅层响应和 `v-memo`。追加推荐时保持旧卡片引用；布局变化和卡片自身交互仍正常更新。

前 10 张推荐封面立即加载，后续使用浏览器原生 lazy；图片解码使用 async。卡片已有的 `content-visibility` 继续保留。没有加入虚拟滚动、删除离屏卡片或改变原列表结构。

验证中，300 张卡片追加到 330 张时，原 300 张卡片的新增渲染次数为 **0**；切换布局仍触发更新。这是组件级回归测试结果，不是实机帧率或整个网页速度的百分比。

`ForYou.vue`、`VideoCard.vue` 的样式块与上一版一致。生产 CSS 长度均为 615248 字节，归一化 Vue 生成的作用域 ID 后内容完全相同。浏览器权限与媒体域名权限保持不变。

参考：[Vue 性能指南](https://cn.vuejs.org/guide/best-practices/performance)、[Chrome 离屏图片说明](https://developer.chrome.com/docs/lighthouse/performance/offscreen-images)。
